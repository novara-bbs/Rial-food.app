## Wave 0 — Bug sweep + dead-code purge

**Commit:** `4d83e94` `fix(wave-0): bug sweep + dead-code purge (Hoy/Cocina/Explora audit)`

17 functional bugs identified during exploration, all fixed:

1. `scan-barcode` CreateModal action was a no-op → wired to `barcode-scanner` navigation.
2. `rial_recipeViewed` key never written → now written on every Recipe-detail entrypoint so the Guided Setup step actually completes.
3. `StoryRingsRow` ignored the tapped story index → viewer now opens at the correct slide.
4. Global notifications badge always lit → renders only when at least one notification is unread.
5. `ImportRecipeURL` silent fallback to fake chicken recipe on parse failure → real error message + 15s timeout + URL validation.
6. `CookMode` crashed on empty `steps` → empty-state guard + WakeLock re-acquire on `visibilitychange` + Escape-to-close.
7. `CookTimer` drifted with backgrounded tabs → `requestAnimationFrame` + `Date.now()` delta timer.
8. `Community` re-read `followedCreators` via `JSON.parse` wrapped in `useMemo([])` → migrated to `useLocalStorageState` so follow toggles are reactive.
9. `handleCreatePost` / `handleAddComment` / `handlePublishStory` hardcoded `'Tú'` / `'Justo ahora'` → use `userProfile.name` + locale-aware `formatRelative()`. `isOwn` detection switched to `author.id === 'self'`.
10. `TodaysMeals` edit/delete buttons invisible on touch (`opacity-0 group-hover`) → always visible, HIG-sized.
11. `createHandleAddToPlan` ignored `recipe.mealType` → mapped to correct slot + time; shopping-list writes go through `aggregateShoppingItems()` to prevent string/object format drift.
12. `PostCard` like/save counters were cosmetic → new `updatePost` handler mutates the post in state; counters now consistent with server intent.
13. `Notifications` rows had `cursor-pointer` but no handler → navigate to `targetType`/`targetId`, mark-read on open.
14. Seed-recipes race clobbered user saves → `rial_seedLoaded` flag aborts re-seed.
15. `Cocina.tsx` type cast `Record<string, any[]>` vs declared `Record<number, any[]>` → fixed.
16. `CreateRecipe` prep/cook-time accepted free-form strings → numeric input with `min=0`.
17. `PostCard` didn't branch on `post.type === 'progress'` → now delegates to `<ProgressPostCard>`.

**Dead code purged:**
- `src/features/social/screens/Creadores.tsx` (no `case 'creadores'` in App.tsx, 0 callers).
- `src/features/home/components/WeightQuickLog.tsx` (`@deprecated Q14`, 0 callers).
- `Home.tsx` dead props `onNavigateToExplore` + `onCheckIn(status?)`.
- `ImportRecipeURL` unreachable `{error && …}` branch.

## Wave 3 — Explora tab polish

**Commit:** `26ba1bd` `refactor(wave-3): Explora tab polish — factory handlers + drift purge + i18n + Discover relocation`

### Handler factory

Inline `useLocalStorageState` calls were scattered across Discover / CreatorProfile / Community / Challenges / ChallengeDetail / CreatorVerification — 4 independent call sites wrote to `followedCreators`, `joinedChallenges`, `challengeJoinDates`, `challengeProgress`. Cross-screen updates were invisible until unmount.

Two new handler factories registered in `AppStateContext`:
- `src/features/social/handlers/creator-handlers.ts` → `createHandleFollowCreator`.
- `src/features/social/handlers/challenge-handlers.ts` → `createHandleJoinChallenge` / `LeaveChallenge` / `CheckInChallenge`.

All 6 consumer screens now read/write via the context. `grep -r "useLocalStorageState\\('followedCreators'" src/features/social/` → 0.

### File relocation

`features/home/screens/Discover.tsx` → `features/social/screens/Discover.tsx` via `git mv` (preserves history). Feature-first compliance.

### Drift purge

- 0 `text-[Npx]` remaining in `src/features/social/**` (was ~55).
- `ProgressPostCard` migrated to `<SectionCard>` (SectionCard baseline 73 → 72).
- 10 social files removed from ESLint Q16 allowlist (fully clean).

### i18n

All `|| 'fallback'` expressions removed from social surfaces:
- `StoryViewer`: `t.stories.{timeNow,timeHourAgo,timeHoursAgo,recovery,strain,closeLabel,tapToAdvance,expired}`.
- `PostCard` aria-labels: `t.social.{likeLabel,unlikeLabel,saveLabel,unsaveLabel,shareLabel,commentLabel,closeCommentsLabel}` + localized `currentLabel` / `sinceLabel`.
- `PostDetail`, `CreatePost`, `CreateStory`, `RecipePicker`, `PublishRecipeSheet`, `Notifications`: removed.
- Added `t.common.close` (was missing).

### A11y — nested buttons

`PostCard` recipe card was inside a clickable card (nested button). Solved with **stretched-link pattern**:

```tsx
<div className="relative">
  {onNavigateToPost && (
    <button type="button" className="absolute inset-0 ... z-0" />
  )}
  <div className="relative p-5 pointer-events-none">
    ...
    <button type="button" className="relative z-10 pointer-events-auto ...">
      {/* recipe card CTA */}
    </button>
  </div>
</div>
```

- Card-level tap = post detail.
- Inner recipe CTA = recipe detail.
- No nested `<button>` in the accessibility tree.

Applied pattern also in `PostDetail` "more posts from creator" (div → button with focus ring).

### Comments dedup

`PostCard` accepts `hideComments?: boolean = false`. `PostDetail` passes `true` so PostDetail owns the canonical comments view; embedded PostCard no longer duplicates the list.

### HIG tap targets

All social interactive elements ≥44×44: PostCard delete / send, PostDetail send / input, CreatePost/CreateStory preview-close / action-bar buttons, RecipePicker close / search, PublishRecipeSheet close / publish, Notifications mark-all.

### Explore subtab persistence

`Explore.tsx` `useState('recipes')` → `useLocalStorageState('exploreActiveTab', 'recipes')`. New localStorage key (not yet in SyncKey — will land with Q6).

### ESLint allowlist

17 entries removed total (10 social + rename Discover + 6 home/cocina wave carry-over). Remaining 7 social entries retain only SectionCard-shape drift:
- `ChallengeDetail` (3), `Challenges` (1), `CreatorProfile` (3), `CreatorVerification` (2), `Discover` (2), `PostDetail` (3), + wellness/profile/planner screens from prior waves.

These will drain in the Q16 codemod sprint.
