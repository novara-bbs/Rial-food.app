# ADR-006 — shadcn new-york style + unified `radix-ui`

- Status: Accepted
- Date: 2026-04-17
- Supersedes: —
- Related: ADR-005

## Context

`components.json` pins:

```
"style": "new-york",
"baseColor": "zinc",
"cssVariables": true
```

The `new-york` preset is shadcn's default since v4 and is the one assumed by the shadcn/ui skill, most community registries, and every AI Elements component. Mixing presets (`new-york` + `default`) inside the same repo breaks CSS variable resolution because the preset also picks the radius scale, focus ring treatment, and ghost button density.

As of `radix-ui` 1.4.3 (installed 2026-01), shadcn consolidated the individual `@radix-ui/react-*` packages into a single `radix-ui` bundle. Components generated with the old CLI import `@radix-ui/react-dialog`; components generated with the new CLI import from `radix-ui`. Mixing both bloats the bundle by ~45 KB gzip and leaves two copies of Radix primitives in memory.

`npx shadcn migrate radix` is a one-shot rewriter that moves all imports to the unified package.

## Decision

All shadcn-sourced components in `src/components/ui/` use the `new-york` preset with `cssVariables: true` and consume Radix primitives via the unified `radix-ui` package. New primitives added with the shadcn CLI must respect this config — agents running `shadcn add` will get the correct code because `components.json` drives the CLI.

The `components.json` fields listed above are not edited casually. A change to `style` or `baseColor` is a design-system event that requires a PR updating `docs/DESIGN-SYSTEM.md`, regenerating all affected components, and running the full Playwright suite.

Individual `@radix-ui/react-*` imports are not lint-banned (too many false positives during transition), but the convention test `src/test/conventions/primitives-export.test.ts` pins the expected import shape for the 14 canonical primitives. Drift in those shows up immediately.

## Consequences

- New components generated by the shadcn CLI match the existing aesthetic out of the box.
- The bundle ships one copy of each Radix primitive.
- Upgrading Radix is a single `radix-ui` version bump instead of 15 individual packages.
- Agents who import `@radix-ui/react-dialog` in new code produce working code — but it's stylistically inconsistent; reviewers redirect to `import { Dialog } from 'radix-ui'`.
- Switching presets (e.g., to `default` or a future `manhattan`) is intentionally hard — it requires deliberate sprint planning, not an inline decision.
